  STEP 4 - AFTER YOU PICK: the tool's own intake questions

  KEY   ( ) single-pick    [ ] multi-pick    ___ free-text    [Other] escape

---------------------------------------------------------------- /blueprint ---
  Opening pick, then 5 fields, one per message.  (arg seeds APP_DESCRIPTION
  and skips the opening pick.)  A picked idea fills all 5: straight to confirm.

  .--[Start]-- how do you want to start? --------------------------------------.
  |  ( ) Describe my app   ( ) Show me examples   ( ) Surprise me              |
  |      examples: 4 random ideas for your language, drawn from 2,600          |
  |      Other = draw 4 new ones                                               |
  '----------------------------------------------------------------------------'
  .--[App description]-- what the app does, domain, target users --------------.
  |  ___  vague -> asked once for the domain and 2-3 core nouns                |
  '----------------------------------------------------------------------------'
  .--[Tech stack]-- primary frameworks, database, infra -----------------------.
  |  ___ e.g. "Next.js + Postgres + Prisma + Vercel"                           |
  '----------------------------------------------------------------------------'
  .--[App type]-- workload class  (8 options) ---------------------------------.
  |  ( ) web app   ( ) API service   ( ) mobile   ( ) CLI                      |
  |      also: data pipeline, desktop, plugin/extension, library               |
  '----------------------------------------------------------------------------'
  .--[Language]-- implementation language  (25 options) -----------------------.
  |  ( ) TypeScript   ( ) Python   ( ) Go   ( ) Rust   ( ) PHP   ...           |
  |      off-list answer -> asked once, then accepted as (custom)              |
  '----------------------------------------------------------------------------'
  .--[Scale]-- concurrent users / req-per-sec / data volume -------------------.
  |  ___ e.g. "100 tenants, ~5k DAU, 50 rps peak"                              |
  |      no numbers -> asked once, then a conservative default (approx)        |
  '----------------------------------------------------------------------------'
  Then: confirmation block, "Proceed? (yes / edit)".  Scaffold and spike ask
  for the work directory, budget and containers before anything runs.

----------------------------------------------------------------- /e2e-tests ---
  5 fields, asked one at a time.  Any field the repository answers is skipped -
  module system, database, session mechanism, env vars and the existing test
  runner's file pattern are all read, never asked.  (arg seeds TARGET_REPO.)

  .--[Repo]-- which application root ------------------------------------------.
  |  ( ) the current directory   ( ) a path I'll give you                      |
  |      skipped when the argument already named a readable path               |
  '----------------------------------------------------------------------------'
  .--[Database]-- how the app stores data -------------------------------------.
  |  ( ) file database (SQLite or similar)   ( ) database server (Postgres,    |
  |      MySQL, ...)   ( ) read the repo and decide                            |
  |      a database server STOPS the run and asks how to get a throwaway one   |
  '----------------------------------------------------------------------------'
  .--[Upstream]-- paid external API, and what to do about fixtures ------------.
  |  ( ) no external API                                                       |
  |  ( ) yes - record real response envelopes (costs money, asks first)        |
  |  ( ) yes - hand-build the fixtures                                         |
  '----------------------------------------------------------------------------'
  .--[Browsers]-- which browser projects to configure -------------------------.
  |  ( ) Chromium only   ( ) Chromium + Google Chrome (default)                |
  |      Chrome install needs root on Linux; on failure the project is dropped |
  '----------------------------------------------------------------------------'
  .--[Git]-- how the work is landed -------------------------------------------.
  |  ( ) branch and commit each step (default)   ( ) branch, no commits        |
  |  ( ) no git - just list changed files                                      |
  |      never pushes, never commits to the default branch                     |
  '----------------------------------------------------------------------------'

  .--[Target]-- Which codebase should I document? -----------------------------.
  |  ( ) Current working directory   ( ) Custom path (then asks path) ___      |
  '----------------------------------------------------------------------------'


----------------------------------------------------- /codebase-to-mermaid ----
  NO questions when a path arg is given.  If empty, one routing question:

  .--[Target]-- Which codebase should I map? ----------------------------------.
  |  ( ) Current working directory   ( ) Custom path (then asks path) ___      |
  '----------------------------------------------------------------------------'


---------------------------------------------------------- /readme-builder -----
  .--[Target]-- which project to document?  (skipped if a path arg passed) ----.
  |  ( ) the current directory   ( ) a different folder (give path) ___        |
  |  [Other]                                                                   |
  '----------------------------------------------------------------------------'
  .--[Output]-- what to do with the result?  (optional) -----------------------.
  |  ( ) write it to README.md in the project folder                           |
  |  ( ) print the Markdown so I can save it myself (default)                  |
  '----------------------------------------------------------------------------'


------------------------------------------------------ /changelog-generator ----
  NO questions.  Runs from the path arg, or the current directory if empty.
  Date/version ranges are rejected - always the full history.


----------------------------------------------------------------- /refactor ---
  One AskUserQuestion call, 3 questions.  (path comes via arg or a plain ask.)

  .--[Focus areas]-- weighted at full depth?  (optional, multi) ---------------.
  |  [ ] Architecture & coupling   [ ] Quality & style                         |
  |  [ ] Complexity & state   [ ] Portability & reuse                          |
  '----------------------------------------------------------------------------'
  .--[Scope]-- what should the analysis cover? --------------------------------.
  |  ( ) Single file   ( ) Whole folder recursively                            |
  |  ( ) PR diff / changed files   ( ) Sampled subset                          |
  '----------------------------------------------------------------------------'
  .--[Depth]-- how deep should each section go? -------------------------------.
  |  ( ) Quick   ( ) Standard   ( ) Deep                                       |
  '----------------------------------------------------------------------------'


--------------------------------------------------------------- /explain-sql ---
  4 fields, asked one at a time.  Only the query is required; the other three
  have defined defaults and may be skipped.

  .--[SQL query]-- the query to review  (paste or path; asked first) ----------.
  |  ___ plain ask, not a menu - STOP for the reply                            |
  '----------------------------------------------------------------------------'
  .--[Recipient role]-- who the explanation is for ----------------------------.
  |  ( ) Data engineer   ( ) Analytics engineer / analyst                      |
  |  ( ) Marketing or ops manager   ( ) Executive (CFO, VP)                    |
  |      skipped -> business analyst with light SQL, stated in one line        |
  '----------------------------------------------------------------------------'
  .--[Business context]-- what it is for, plus schema or DDL if available -----.
  |  ( ) Revenue or finance reporting   ( ) Product or user analytics          |
  |  ( ) Operational monitoring   ( ) No context - review the SQL alone        |
  |      skipped -> completeness check reports NOT ASSESSABLE                  |
  '----------------------------------------------------------------------------'
  .--[SQL dialect]-- which engine to judge the syntax against -----------------.
  |  ( ) PostgreSQL   ( ) BigQuery   ( ) Snowflake   ( ) MySQL                 |
  |      skipped -> names the dialect assumed and flags the verdict            |
  '----------------------------------------------------------------------------'


------------------------------------------------------------ /docblock-rewrite -
  NO questions.  Runs from a path/flags argument via a bundled bash script
  (defaults to a dry-run on the current directory if empty).


-------------------------------------------------------------- /code-teacher ---
  NO menu until code is in hand.  If no code arg, one plain prompt (STOP for
  reply) that also asks for the bugs and design decisions behind the code.

  .--[Code]-- paste the code to annotate, or give a file path -----------------.
  |  ___ plain ask, STOP for the reply.  Not source code, or code built to     |
  |      do harm, means it says so and stops                                   |
  '----------------------------------------------------------------------------'
  .--[Audience level]-- who the comments are pitched at  (optional) -----------.
  |  ( ) Beginner in this language   ( ) Intermediate (default)                |
  |  ( ) Experienced, new to this codebase                                     |
  '----------------------------------------------------------------------------'
  .--[Dev notes]-- bugs hit, surprises, ordering that mattered  (optional) ----.
  |  ( ) Nothing to add   ( ) I'll describe them                               |
  |  Anything you state is written as fact; anything inferred carries          |
  |  INFERRED: and must point at a real line.                                  |
  '----------------------------------------------------------------------------'
  .--[Output]-- four sections, fixed order ------------------------------------.
  |  Plan (<=8 lines) . one fenced code block . Teaching Points (3-5) .        |
  |  Verification.  Original code returned unchanged, comments only.           |
  '----------------------------------------------------------------------------'

------------------------------------------------------------ /fullstack-readme -
  2 fields, asked one at a time.  A path argument seeds TARGET and skips it.

  .--[Target]-- which web app -------------------------------------------------.
  |  ( ) the current directory   ( ) a folder or .zip I'll give you            |
  |      no screens and no API STOPS the run in one sentence; more than one    |
  |      unrelated app lists their names and asks which                        |
  '----------------------------------------------------------------------------'
  .--[Output]-- where the README goes -----------------------------------------.
  |  ( ) print the README (default)   ( ) write README.md into the folder      |
  |      an existing README.md is confirmed before it is overwritten           |
  '----------------------------------------------------------------------------'
  .--[Result]-- three parts, nothing else -------------------------------------.
  |  # Name . 2-4 sentence description . ## plain-English categories, largest  |
  |  first, one-sentence bullets.  Two passes over every file; only features   |
  |  traced to real code.  No emoji, no en/em dashes, no hype words.           |
  '----------------------------------------------------------------------------'


--------------------------------------------------------------- /explain-regex -
  Up to 4 fields.  Only the regex is required; an argument seeds it (plus any
  flavor, use case, or chat/file words after it).  Nothing is analyzed until
  the output question is answered.

  .--[Regex]-- the pattern to explain  (plain ask; asked first) ---------------.
  |  ___ plain ask, not a menu - STOP for the reply.  Never guessed            |
  '----------------------------------------------------------------------------'
  .--[Output]-- where the teardown goes  (asked before any analysis) ----------.
  |  ( ) Chat - print the teardown here                                        |
  |  ( ) File - save to REGEX-EXPLAINED.md                                     |
  '----------------------------------------------------------------------------'
  .--[Flavor]-- optional, never blocks ----------------------------------------.
  |  ___ JavaScript, Python, PCRE, Go, .NET ...                                |
  |      skipped -> common PCRE / JS / Python subset, stated in one line       |
  '----------------------------------------------------------------------------'
  .--[Use case]-- optional, never blocks --------------------------------------.
  |  ___ e.g. "validating emails on a signup form"                             |
  |      skipped -> best guess stated as an assumption                         |
  '----------------------------------------------------------------------------'
  .--[Result]-- 11 numbered sections, every example engine-checked ------------.
  |  Summary . tokens . structure . valid / invalid examples . walkthrough .   |
  |  pitfalls . ReDoS verdict . alternatives . context . plain rewrite.        |
  '----------------------------------------------------------------------------'


------------------------------------------------------------- /script-refactor -
  NO menu when an argument names scripts (paths, a folder, or a glob).  With
  no argument, one question.  Everything else is inferred from the scripts,
  read from their callers, or defaulted.

  .--[Scripts]-- which scripts to refactor  (only with no argument) -----------.
  |  ( ) All scripts in ./scripts   ( ) One script (give path)                 |
  |  ( ) Changed scripts only (git diff)                                       |
  '----------------------------------------------------------------------------'
  .--[Checks]-- before anything is written ------------------------------------.
  |  Callers searched for what they read . copies refactored in a temp         |
  |  workspace . old and new run side by side with compare-runs.sh . every     |
  |  case must show result: same                                               |
  '----------------------------------------------------------------------------'
  .--[Result]-- report, then STOP for approval --------------------------------.
  |  Intake . per script: diff, contract check, comparison, changes,           |
  |  skipped . numbered behavior fixes, safety first . cross-script findings.  |
  |  Originals untouched until approved; fixes apply only by number.           |
  '----------------------------------------------------------------------------'

------------------------------------------------------------- /blueprint-forge -
  NO menu when the argument says scan or rebuild, or names a repo or a
  *.BLUEPRINT.md file.  Otherwise one question.  Rebuild asks for the
  blueprint only when none can be found.

  .--[Mode]-- scan or rebuild  (only when the argument does not say) ----------.
  |  ( ) Scan a codebase   ( ) Rebuild from a blueprint                        |
  '----------------------------------------------------------------------------'
  .--[Scan]-- repo -> BLUEPRINT.md --------------------------------------------.
  |  Manifests and lockfiles first . every source file opened . 14 fixed       |
  |  sections . secrets [REDACTED] . self-check list . check-blueprint.mjs     |
  |  must print PASS before the checklist is written.                          |
  '----------------------------------------------------------------------------'
  .--[Rebuild]-- BLUEPRINT.md -> app, STOP after the plan ---------------------.
  |  Build order . Open Questions answers . version swaps . target folder and  |
  |  stack shown as defaults.  After approval: one step at a time, each step   |
  |  verified, then a handoff listing every guess and substitution.            |
  |  Then, on request only: rescan the rebuild and compare-blueprints.mjs      |
  |  lists every endpoint, model, and env var that went missing.               |
  '----------------------------------------------------------------------------'
