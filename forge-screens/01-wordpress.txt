--------------------------------------------------------------- /wp-menu-icons -
  NO questions.  Runs from the current directory (or a theme path as arg),
  auto-detects classic-vs-block and the install mode, then ports the picker.

  Precheck first: block/FSE themes (Navigation block) are rejected before any
  file is touched.  Mode is auto-picked, not asked:

  .--[Mode A]-- theme already has an icon field + renderer --------------------.
  |  swap the plain text input for the picker, reuse the meta key, no frontend |
  |  change.                                                                   |
  '----------------------------------------------------------------------------'
  .--[Mode B]-- theme has no icon field ---------------------------------------.
  |  install the full admin side, add a reader helper, write                   |
  |  MENU-ICON-FRONTEND.md with two render options.  Templates NOT auto-edited.|
  '----------------------------------------------------------------------------'


-------------------------------------------------------------- /wp-performance -
  NO questions.  Runs from a file path (arg) or the current directory.
  Every run is COLD: the manifest is rebuilt, every file is re-read from disk,
  and prior findings/reports/clean verdicts are ignored.  Run it twice and the
  second pass is independent, not a replay.

  .--[Step 1]-- coverage manifest ---------------------------------------------.
  |  scripts/wp-perf-manifest.sh <target>  ->  every .php .inc .js .jsx .ts    |
  |  .tsx .json with line counts.  Prunes vendor/, node_modules/, dist/,       |
  |  build/, coverage/, *.min.*, lock files.  --all keeps build output.        |
  |  This list IS the checklist: nothing outside it, nothing skipped inside.   |
  '----------------------------------------------------------------------------'
  .--[Step 2]-- grep triage  (ordering only, never a verdict) -----------------.
  |  scripts/wp-perf-scan.sh <target>  ->  CRITICAL / WARNING / INFO hits.     |
  |  Decides which files get read first.  A match is a candidate, not a find.  |
  '----------------------------------------------------------------------------'
  .--[Step 3]-- read every manifest file, in full -----------------------------.
  |  Top to bottom, >1500-line files in sequential chunks, batches of ~10.     |
  |  Catches what grep cannot: N+1 in loops, wrong request context, missing    |
  |  caching, per-request DB writes.                                           |
  '----------------------------------------------------------------------------'
  .--[Output]-- findings + mandatory coverage line ----------------------------.
  |  Scan: cold run . <N> files read / <N> in manifest . <N> total lines       |
  |  CRITICAL / WARNING / INFO, each with file:line + quoted code + Impact +   |
  |  Fix.  Max 5 per band.  Any unread file is named with its reason.          |
  '----------------------------------------------------------------------------'


-------------------------------------------------------------- /wp-report-card -
  NO questions.  Runs from a file path (arg) or the current directory,
  auto-detects target type, reads files directly.  Same detection and reading
  as /wp-review, but the output is ONLY the scorecard:

  .--[Output]-- one table, nothing else ---------------------------------------.
  |  10 areas scored x/10 (Security, Performance, Architecture, Correctness,   |
  |  WP Standards, Maintainability, Documentation, Testing, Accessibility/UX,  |
  |  i18n) + an Overall row + one Tier line.  No findings, no fixes, no prose. |
  '----------------------------------------------------------------------------'

-------------------------------------------------------------------- /wp-grade -
  NO menu.  Submission comes from the arg, a file path, or a plain ask.

  .--[Code]-- paste the WordPress code to grade, or give a file path ----------.
  |  ___ plain ask, STOP for the reply.  Not WordPress code means it says so   |
  |      and stops - no grade.  Too large means partial review + where it      |
  |      stopped + an offer to continue.                                       |
  '----------------------------------------------------------------------------'
  .--[Output]-- six sections, fixed order -------------------------------------.
  |  Purpose . Grade (A-F with +/-) . Strengths . Weaknesses . Nitpicks .      |
  |  Verdict.  Six-point safety scan first (escaping, sanitization, nonces,    |
  |  capability checks, $wpdb->prepare(), queries in loops); any hit is a      |
  |  Weakness, never a Nitpick, and moves the grade.                           |
  '----------------------------------------------------------------------------'
