# Checker specification

The bundled checker in `scripts/checker/` implements this spec. Read this file only when the bundled checker cannot be used (for example, it is missing or fails its self-test in a way you cannot explain) and you must write your own, or when you need to understand a checker failure.

## Setup

`verify.mjs` is an ES module: use `import`, and use `createRequire(import.meta.url)` if you need `require`. For JS parsing, install `@babel/parser` into `<scratchpad>/checker/` and use it (`sourceType: 'unambiguous'`, plugins `jsx` for `.js` / `.jsx` / `.mjs` / `.cjs`, `typescript` plus `jsx` for `.tsx`, `typescript` for `.ts`, `tokens: true`). Do not use prettier internals.

## verify.mjs

`node <scratchpad>/checker/verify.mjs <orig-dir> <current-dir> [files…] [--terse [--max-doc-lines <n>] [--checked-php] [--checked-js]]` compares each original file with the current one and runs three checks (`--checked-php` and `--checked-js` mean a tool reads the doc types of that language's files; `--checked-types` means both):

1. **Code check.**
   - PHP: tokenize with `token_get_all()` (in `php-tokens.php`). Drop `T_COMMENT`, `T_DOC_COMMENT` and `T_WHITESPACE`, and keep every other token verbatim, including `T_INLINE_HTML` (template markup outside `<?php ?>`) byte for byte, because whitespace there is real output. Compare the two token lists.
   - JS: deep-compare the Babel ASTs after dropping the keys `start, end, loc, range, comments, leadingComments, trailingComments, innerComments, extra, tokens, errors`.
2. **Layout check.** This catches reformatting, which the code check ignores. Remove every comment from both versions together with the spaces and tabs right after it (for a PHP `//` or `#` comment that ends in a newline, keep the newline), strip trailing whitespace from each line, drop empty lines, and compare the remaining lines exactly, including indentation. A docblock opened mid-line therefore passes only when the code after `*/ ` keeps its original line.
3. **Comment-is-code check.** Anchor every comment to the index of the next code token (from the code check's token list, so anchors match across versions when the code check passes).
   - **Frozen** comments must be identical: same text, same anchor, nothing added, nothing removed. For a `translators:` comment, it must also still be the last comment before its anchor. One exception: a new `translators:` comment is allowed when the code after it reaches a gettext function call (`__`, `_e`, `_x`, `_n`, `esc_html__` …) before the end of its statement (`;`, `{` or `}`), so it may sit before the statement or before an inner line of it.
   - **Frozen tag lines** inside docblocks (one line each, trimmed) must be identical as a multiset per anchor: nothing added, nothing removed.
   - **Kept tag lines** in the original must still exist at the same anchor. Adding new ones is allowed.
   - **Header fields** that WordPress reads with `get_file_data()` (plugin, theme, page-template and block pattern headers: `Plugin Name:`, `Theme Name:`, `Template Name:`, `Title:`, `Slug:` etc.) are frozen tag lines wherever they appear, so none may be added, removed or edited.

4. **Terse check** (only with `--terse`; without it the output is exactly the full-style output). It runs after the other checks, on files whose code matched. Only new or edited doc comments (`/** */`) are checked: a comment is skipped only when the original has the same text at the same anchor, so a copy of another comment placed above new code counts as new. The limit also skips a comment where every line repeats a line of a changed original comment; the tag rule does not. Frozen whole comments (WP-CLI help, translators, licenses, directives) are skipped. A hook docblock is exempt from both rules below: its statement reaches a hook call (`do_action`, `do_action_ref_array`, `do_action_deprecated`, `apply_filters`, `apply_filters_ref_array`, `apply_filters_deprecated`, not as a method) with nothing before it but an assignment target (`$x =`, `$this->x =`, `$q['k'] =`, `$a[ $k ] =`, `self::$x =`, `static::$x =`, `Foo::$x =`, the compound forms), a cast, `return`, `echo`, `print`, `!`, or one `if (` that opens the statement. A hook call inside an array, an arrow function, a closure or another call's arguments does not make the docblock a hook docblock.
   - **Limit.** Count the prose rows of the comment (markers removed). Not counted: blank and marker-only rows (rules, and a lone `{` or `}`); Frozen and Kept tag lines; a `This … is documented in …` line; a `@var` line of a template's file header; a `@global` line the original comment at the same anchor had; with `--checked-php` (in PHP files) or `--checked-js` (in JS files), a `@param`, `@return`, `@throws` or `@var` line the original had (matched as below); and the rows that continue one of those (up to a blank row or the next `@` tag; when the line opens a hash with `{`, as `@var array $args {` does, up to the matching `}`, blank rows included, or up to the next `@param`, `@return`, `@throws` or `@var` row when the hash is never closed). The limit is `--max-doc-lines <n>` or `--max-doc-lines=<n>` (default 3, a whole number of at least 1, else exit 2), and twice that for the file header. Over the limit prints `LONG DOC COMMENT: <file>:<line> (<k> > <n> lines)`, where `<line>` is the comment's first line.
   - **File header.** PHP: the doc comments between the first `<?php` and the first statement, except the last one when that statement is a declaration (`class`, `function`, `const`, a modifier or an attribute), which is the declaration's own, or, outside templates, a variable assignment (`$count = 5;`) that follows the doc comment directly. A doc comment above that assignment is still the file header when a blank line separates them or it has a `@package` / `@subpackage` line. JS: the doc comments before the first token, with the same exception for a function, class or export.
   - **Templates.** A PHP file is a template when it sits under a `template-parts/`, `templates/`, `views/` or `partials/` folder, is a theme root file other than `functions.php` (the current directory's `style.css` has `Theme Name:`), has HTML outside `<?php ?>`, or has no class or named function. Only a template's file header `@var` lines are exempt from the limit and the tag rule; in any other file a new `@var` line in the header is `TERSE TAG ADDED`.
   - **Tags.** A new `@param`, `@return`, `@returns`, `@throws` or `@var` row prints `TERSE TAG ADDED: <file>:<line> <tag>`, on every tag row of an edited comment (not only rows whose text is new), unless the original has a comment at the same anchor with the same key: tag plus name (`@param int $id` and `@param {number} [id]` key on `$id` and `id`), or tag plus type for a tag with no name (`@return int`, `@throws Exception`, a `@var int` with no variable; `@returns` and `@return` are the same tag). So a kept `@param int $id` with a shorter description passes, and a changed return type fails. The rule applies with `--checked-php` and `--checked-js` too: an existing typed tag stays, a new one fails.

Print `CODE CHANGED: <file>`, `LAYOUT CHANGED: <file>:<line>` or `FROZEN COMMENT CHANGED: <file>: <text>` for each failure (and in terse style the two lines above), then `OK: N files, code identical` or `FAILED: n problem(s) in N files`, counting every line. Exit non-zero on any failure.

The Frozen and Kept classes are defined under **Preserve** in `rules-core.md`.

## coverage.mjs

`node <scratchpad>/checker/coverage.mjs <project> [--no-since] [--terse] [files…]` scans the given files (relative to `<project>`), or every file when none are given. It prints one `MISSING …` line per gap followed by `GAPS: n` and exits 1, or prints `OK: N files fully documented` and exits 0. A gap is:

- PHP (tokenizer): every `class` / `interface` / `trait` / `enum`, named `function`, `function` closure, `const`, and property declaration not directly preceded by a `T_DOC_COMMENT` (allowing for modifiers and attributes such as `public`, `static`, `final`, `abstract`, `readonly`, `#[…]`); every hook call with no docblock and no `This … is documented in` line before its statement; and, unless `--no-since` is passed, every docblock missing `@since`. WP-CLI command classes, their public methods, and closures passed to `WP_CLI::add_command` (directly, or through a variable the file passes to it) are skipped, and verify freezes their docblocks, since WP-CLI prints them as help text. A file with no docblock between `<?php` and the first statement, or with only one when that statement is a declaration (`class`, `function`, `const`, a modifier or an attribute) or a closure stored in a variable (`$cb = function`), gets `MISSING FILE DOCBLOCK`: that one docblock is the declaration's. Arrow functions are not scanned (their rule needs judgement).
- JS (Babel AST): every file with no header comment (a single `/** */` above a first statement that is itself a declaration needing a doc is that declaration's, unless a directive such as `'use strict'` comes first), and every `FunctionDeclaration`, class method, top-level or exported `const`-bound function or class, and `ns.member = function` assignment with no leading `/** … */` comment.
- With `--terse`, only public declarations are reported; a skipped declaration gets neither `MISSING DOCBLOCK` nor `MISSING @since`. PHP skips `private` and `protected` methods, properties and class constants, and every `function` closure that is not an argument, at any depth, of a registration call (`add_action`, `add_filter`, `register_rest_route` including its `callback` array, `add_shortcode`, `register_block_type`, the activation, deactivation and uninstall hooks, `WP_CLI::add_command`, the admin menu, meta box and Settings API functions, `register_setting`, `register_meta` and its post and term forms, `register_post_type`, `register_taxonomy`, `register_block_bindings_source`, `spl_autoload_register`, `register_shutdown_function`). A closure assigned to a variable (`$cb = function …`, `static function` included) counts as public when the same file passes that variable to one of these calls (`add_action( 'init', $cb )`). Classes, interfaces, traits, enums, named functions and hook calls are always reported, so a hook fired with only a `//` comment above it is still a gap: the checker enforces that hooks keep their docblock. JS skips a declaration whose top-level statement is not exported (`export`, `export default`, `module.exports`, `exports.x`, `window.x`, or a name exported elsewhere), anything inside a function body, and `private`, `protected` and `#name` class members; an `ns.member = function` assignment is public unless it sets `this.x`, because WordPress scripts publish through namespaces and `$.fn`, often inside an IIFE. The file docblock and the JS file header stay required, and `--no-since` works as before.
