## JavaScript rules

- **Coverage:** a file header comment (summary, a blank ` *` line, the module's role and what it exports or attaches: globals, namespace members, registered blocks / stores / REST calls, then `@since` per the policy). JSDoc on every function: namespace members, named and local functions, IIFE wrappers, class methods, React components and hooks, and any arrow or anonymous callback with a multi-statement body or a non-obvious purpose (event handlers, AJAX done/fail, `useEffect` bodies, `registerBlockType` `edit` / `save`). Trivial one-expression arrows such as `(x) => x.id` don't need JSDoc.
- **Tags:** `@since`. `@param {Type} name Description.` for every parameter, with `[name]` for optional ones, `[name=default]` for defaults, `{...*}` for rest, and dotted names (`props.attributes`) for destructured objects. `@return {Type} Description.` (`{void}`, `{Promise<…>}`, `{jqXHR}`, `{JSX.Element}`, `{Element}`).
- **Shared shapes:** add `@typedef` / `@type` for localized config objects (shape taken from the PHP `wp_localize_script` / `wp_add_inline_script` / `wp_set_script_translations` call), block attributes (from `block.json`), data records and state fields. Put each shared `@typedef` only in the file the rules file names for it.
- **WordPress JS docs** (`@wordpress/eslint-plugin` present, or a WPCS PHP profile with no JS config): tabs. Summaries in the third person ending with a period. Use `@return` (never `@returns`). Types in `{}`. Follow the `@wordpress/eslint-plugin` `jsdoc` rules, which must pass if ESLint is installed.
- **ES5 / jQuery legacy:** document `var`-style functions, `$.fn` plugins (`@memberof jQuery.fn`), and `$(document).ready` / `$(function () {…})` bodies. Don't suggest ES6 rewrites in comments.
- **TypeScript (`.ts` / `.tsx`):** use TSDoc-style comments. **Don't repeat types already in the signature.** Write `@param name - Description.` without `{Type}` and `@returns Description.`, per TSDoc. Use `@remarks`, `@example` and `@throws` as needed.
- **Inline comments:** `//` full sentences ending with a period, explaining why: escaping before `.html()` / `innerHTML` / `dangerouslySetInnerHTML`, race or stale-response guards, debouncing, sequencing, and fallbacks.
