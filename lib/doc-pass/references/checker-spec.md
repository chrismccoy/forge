# Checker specification

The bundled checker in `scripts/` implements this spec. JS / TS and Vue / Svelte / Astro scripts are parsed with Babel (`lib.mjs`); every other language is parsed with tree-sitter (`treesitter.mjs`, settings in `langs.mjs`). Both produce the same model, so `verify.mjs`, `coverage.mjs` and `selftest.mjs` handle every language with one command line. Read this file only when the bundled checker cannot be used (it is missing, or fails its self-test in a way you cannot explain) and you must write your own, or when you need to understand a checker failure.

## Command reference

- `node verify.mjs <orig> <current> [--schema-tags] [--checked-types] [--line-limit <n>] --files-from <list>` prints `CODE CHANGED`, `LAYOUT CHANGED`, `FROZEN COMMENT CHANGED` or `LONG COMMENT LINE` lines and then `FAILED: n problem(s) in N files`, exiting non-zero, or prints `OK: N files, code identical (n frozen comments/lines protected)`.
- `--list-frozen` also prints `LOCKED: <file>: <n> region(s) …: lines <a-b>, …` and `FROZEN: <file>:<line> <text>` lines.
- `node verify.mjs <dir> --list-files [--list-skipped]` prints the file walk (and `SKIPPED: <file>` lines for binary or generated files, `SKIPPED DIR: <dir>/` lines for pruned folders named like build output — `build`, `dist`, `out`, `target`, `coverage`, `obj`, `vendor`, `__generated__` — that hold source files) and checks nothing.
- `node coverage.mjs <project> [--since] [--line-docs] --files-from <list> [--context-from <list>]` prints `MISSING FILE HEADER`, `MISSING DOCBLOCK`, `MISSING PACKAGE DOC` (Go), `MISSING @since` or `UNPARSABLE` lines and `GAPS: n`, plus uncounted `LOCKED DOC` and `READ BY HAND` lines, or `OK: N files fully documented`; `LOCKED DOC` lines name undocumented declarations whose doc slot is locked and are not gaps: one that starts inside a locked region, or one locked as the neighbour of the broken statement before it (a comment added between them joins the region). A declaration locked on its own (the declaration case below) is a gap: its doc slot is outside the region. A file the grammar or reader throws on prints `UNPARSABLE: <file>: <reason>` and the run goes on; for a `--context-from` file the line goes to stderr and is not a gap. `--context-from` files are read (documented C / C++ header prototypes, Go package docs) but never reported. `--line-docs` accepts plain `//` / `#` comments above a declaration as its doc.
- `node selftest.mjs <project> <work-dir> [--schema-tags] [--checked-types] --files-from <list>` prints `PASS` / `FAIL` / `SKIPPED` per case and ends `SELFTEST OK` or `SELFTEST FAILED`; with no parsable file in the list it prints only `FAIL: no parsable in-scope files to test with` and exits 1.
- A `--files-from` list that is empty means no files, never the whole tree; a list file that does not exist exits 2. Flags may come before or after the folders. A value flag (`--line-limit`, `--files-from`, `--context-from`) with no value, or a `--line-limit` that is not a whole number, exits 2.

## Setup

ES modules (`"type": "module"`); use `createRequire( import.meta.url )` if `require` is needed. Install `@babel/parser`, `@vscode/tree-sitter-wasm` (maintained WebAssembly grammars and the ABI-15 runtime) and `tree-sitter-wasms` (older grammars for Kotlin, Swift, Dart, Elixir and C, which the same runtime loads) into `<scratchpad>/checker/`. Do not use prettier internals or TypeScript's compiler API (a version mismatch with the project would change results).

Every tool accepts `--files-from <list>` (one relative path per line; blank lines and `#` comments ignored) in addition to files on the command line. With no files at all, it walks the tree: it never follows symlinks, and skips `node_modules`, `bower_components`, `jspm_packages`, `vendor`, `build`, `dist`, `out`, `coverage`, `storybook-static`, `__generated__`, `target`, `__pycache__`, `venv`, `site-packages`, `obj`, `Pods`, `DerivedData`, `cmake-build-*`, Laravel's `bootstrap/cache/` and `storage/framework/`, and every dot folder; files named `Kconfig*`, `_ide_helper*.php`, `.phpstorm.meta.php`, and, for JS / TS extensions only, `*.min.*`, `*.bundle.*`, `*.generated.*`, `*.gen.*`; Vite `*.timestamp-*.mjs`, `next-env.d.ts`, `auto-imports.d.ts`, `components.d.ts`, `typed-router.d.ts`, `worker-configuration.d.ts`; and files whose first 2 KB contain a NUL byte (binary data with a source extension, such as `.ts` MPEG video fixtures) or whose first 20 lines carry a generated marker. A marker either starts a line, after any comment marker (`@generated`, `Code generated`, `DO NOT EDIT`, `DO NOT MODIFY BY HAND`, `GENERATED CODE`, `<auto-generated`, `auto-generated` / `autogenerated`, `This file is (auto-)generated`, `Generated by Django`, `Generated for Laravel`; case-insensitive), or sits anywhere in a comment line (`DO NOT EDIT` and `@generated`, case-sensitive; `this file was generated`, `do not edit by hand / manually / directly`, case-insensitive). Prose further down a file, and a string that does not start its line, never count (a line that starts with a marker counts even inside a docstring). `node verify.mjs <dir> --list-files` prints that walk, one relative path per line, and checks nothing; the skill builds `files.txt` from it.

## Parsing

- Language by file: `.ts` / `.mts` / `.cts` → TypeScript; `.tsx` → TypeScript + JSX; `.d.ts` / `.d.mts` / `.d.cts` → TypeScript with `{ dts: true }` only; everything else → JSX (plus `flow` when a `@flow` pragma is in the first 4 KB).
- Plugin sets, tried in order. TS: `decorators-legacy` (NestJS, TypeORM, Angular parameter decorators), then `decorators` (`export @dec class`). JS: `jsx` + `decorators-legacy`, then `jsx` + `decorators`, then `decorators-legacy` without `jsx`. Every set except `.d.ts` adds `explicitResourceManagement`. Options: `sourceType: 'unambiguous'`, `tokens: true`, `errorRecovery: false`, `allowReturnOutsideFunction`, `allowAwaitOutsideFunction`, `allowUndeclaredExports`.
- The current version of a file is parsed with the plugin set the original used first, so both are parsed alike.
- **Components** (`.vue`, `.svelte`, `.astro`): a top-level script block is a `<script …>` tag at the start of a line (attribute values may contain `>`, as in `generic="T extends Record<string, unknown>"`) up to its `</script>`. `lang="ts"` / `tsx` picks TypeScript. The **markup** is the file with each script body replaced by a placeholder; it must be byte-identical. A `<script>` that does not start a line is part of the markup. **Astro** (`.astro`): the frontmatter between `---` fences at the top of the file is a TypeScript block, and `<script>` tags count even when indented (TypeScript); a script with any attribute other than `src` (`is:inline`, `type="module"`, `define:vars`) is sent to the page as written and stays in the markup. In every component kind, a self-closing `<script … />` and a script whose `type` is not JavaScript (`application/ld+json`) stay in the markup.
- A plain JS / TS file Babel cannot parse in its original form (invalid syntax, or a template named `.js`) is parsed with the tree-sitter JavaScript, TypeScript or TSX grammar instead, and its current version too, with comments classified by the JS rules. Its broken regions are locked byte for byte and printed as `LOCKED:` when tree-sitter finds any; a file tree-sitter parses cleanly gets no `LOCKED:` line. Coverage cannot scan it and prints `READ BY HAND: <file>: …`, which is not counted in `GAPS`. It is reported as `CODE CHANGED: <file>: original parse error …` only when tree-sitter fails too. A current file that no longer parses while its original did is `CODE CHANGED`. A component `<script>` block Babel cannot parse is `CODE CHANGED: <file>: original <script> block N: parse error …`, and coverage counts it as `UNPARSABLE`; such a file must leave the scope.

## Tree-sitter languages

- Grammars: PHP, Python, Go, Rust, Ruby, Java, C#, C++, PowerShell from `@vscode/tree-sitter-wasm`; Kotlin, Swift, Dart, Elixir, C from `tree-sitter-wasms`. Languages with no usable wasm grammar have a reader in the checker that builds nodes with the same API: Clojure (`clojure.mjs`, a full reader), and Erlang, Haskell, Perl and Lua (`lexers.mjs`: a lexer that groups tokens into top-level forms, so comments between forms are their siblings). Lua uses the lexer because the bundled grammar gave different trees for the same text.
- **Parsing.** One parser per language, and every tree is freed after use (wasm memory is not garbage-collected; without this a large repository aborts in `ts_malloc`). The first source per language is parsed once and discarded, because a grammar's first parse can differ from later ones. For `tree-sitter-wasms` grammars, each source is parsed until two consecutive parses agree (at most five times); if none agree, the language's parser is replaced by a fresh, warmed-up one and the source is tried once more (a long run can leave a grammar's scanner in a bad state); only then is the file reported as a parse error rather than trusted. `langs.mjs` maps extensions and bare file names (`Rakefile`, `Gemfile`) to a language; `.blade.php` is excluded.
- **Code stream.** Walk the tree. A node whose type contains `comment` is a comment (not descended). In Python, a docstring (an expression statement holding one plain string, first in a module, class or function body) is a comment too; so are an Elixir `@moduledoc` / `@doc` / `@typedoc` attribute with a string or `~s` / `~S` sigil value, and a Clojure docstring (the string after the name in `defn`-style forms, after the name in `def` when a value follows, last in a `defprotocol` method). Every other named node adds an open and a close marker with its type; every leaf adds its type and text; and any non-blank text a node holds between its children (Dart keeps string contents this way) adds a `text` token, with whitespace kept inside string nodes. The streams must be identical. Node positions are JS string indices, so comment ranges feed the same layout check as JS; a trailing line break inside a comment node is dropped from its range.
- **Locked regions.** For each `ERROR` or missing node, climb its parents. On reaching a container (`declaration_list`, `field_declaration_list`, `enumerator_list`, a preprocessor conditional, a statement list or block, a class / enum / interface / struct / protocol / object / trait / impl / module body, or the root), lock the statement that holds the error, its nearest non-comment siblings and the comments between them (for a missing node, a zero-width token the grammar inserted, such as the `;` after a `ZTEST(…) { … }` macro, only the statement). On reaching a declaration first (a node whose type names a function, method, item, definition, declaration, class, module, impl, trait, struct, enum, interface, namespace, lambda or closure), lock that declaration. A root that is itself an `ERROR` (the file failed to parse as one unit) is treated as a container, not locked whole. Each locked node enters the stream as one token holding its exact source text, comments included. `--list-frozen` prints a line that starts with `LOCKED: <file>: <n> region(s)` and ends with the regions' line ranges (`: lines 12-30, 45`).
- **Anchors.** A comment's anchor is the index of the next stream token; a trailing comment (on the same line as the previous leaf) gets the anchor with a `~` suffix, so moving it to its own line is a change.
- **Classification** (`classifyTs`): the comment body is its text without markers (`//`, `///`, `//!`, `/*`, `/**`, `*/`, `#`, PowerShell `<#` / `#>`, docstring quotes, leading `*`). The language's `whole` patterns, tested on the first body line, and the shared license / `@generated` line patterns, tested on every line, freeze the comment whole. `frozenLine`, `keptWhole`, `keptTyped` and (with `--checked-types`) `checkedTyped` classify single tag lines; PHP typed tag lines keep `@tag Type $name`; a callable type keeps its return type (`@param callable(int): bool $cb`); `@method` keeps its signature up to the closing `)`, `@phpstan-type` / `@psalm-type` / `@*-import-type` / `@template*` keep the whole line, and Lua `@tparam` keeps `@tparam type name`. A comment body starting `#!` is frozen whole. In a Python file that imports `ply` (vendored copies such as `from .ply import yacc` included) or calls `lex.lex(`, `yacc.yacc(` or `TOKEN(`, every docstring is frozen whole (rule docstrings are token regexes and grammar productions); in one that imports `docopt`, the module docstring is. Doctests are frozen lines: Python `>>>` / `...` and Elixir `iex>` / `...>` prompts in docstrings, Haskell `>>>` / `prop>` in comments (followed across consecutive line comments), each with its expected output up to a blank line. `wholeRaw` and `keptRaw` patterns test the raw text (markers kept) for forms the stripped body cannot tell apart: shebangs, `;!zprint`, `{-# pragmas #-}`, `## no critic`, LuaLS `---@param`.
- **Context rules** (`postProcess`): Rust doc comment lines inside a fenced block (between ```` ``` ```` lines in consecutive doc comments) are frozen whole (doctests). Go comments inside a function named `Example…` (expected output) and the comment block directly above `import "C"` (cgo preamble) are frozen whole.
- **Next-line directives** come from the language's `nextLine` pattern; only directives on their own line (anchor without `~`) must stay last before their code.

## Comment classes (JS / TS)

- **Frozen whole**, anchored at the start of the comment: ESLint / JSHint / global / exported comments, `eslint-disable` / `-enable`, Biome / Deno / oxlint / tslint / stylelint / cspell / noinspection / `language=` comments, `@ts-*`, triple-slash `/// <reference|amd-module|amd-dependency`, `prettier-ignore`, `istanbul` / `c8` / `v8` / `node:coverage` ignore comments, `translators:`, `i18next-extract-*`, `/*#__PURE__*/`-style annotations (`PURE`, `NO_SIDE_EFFECTS`, `INLINE`, `KEY`), webpack / Turbopack magic comments, `/* @vite-ignore */`, `@refresh reset`, `@flow` / `@noflow`, template language hints (`/* GraphQL */`, `/* sql */` …), and `/*! … */`.
- **Frozen whole** when any line of the comment starts with: `@jsx…` pragmas, `@openapi`, `@swagger`, apiDoc `@api {…}` / `@apiX`, `@generated`, `@preserve`, `@license`, or license text (`Copyright`, `(c) <digit>`, `©`, `SPDX-License-Identifier`, GNU GPL, `Permission is hereby granted`, `Licensed under the`).
- **Frozen tag lines:** `@jest-environment*`, `@vitest-environment*`, `@format`, `@prettier`, `@noformat`, `@deprecated`, `@internal`, `@hidden`, `@ignore`, `@public`, `@alpha`, `@beta`, `@experimental`, `@private`, `@protected`, `@readonly`, `@override`, `@sealed`, `@virtual`. With `--schema-tags`, also the validation and schema tags listed in `lang/js.md`.
- **Kept lines:** `@since`, `@see`, `@link`, `@author`, `@packageDocumentation`, `@module` (whole line). Type-bearing tags (`@typedef`, `@callback`, `@type`, `@satisfies`, `@template`, `@this`, `@enum`, `@augments`, `@extends`, `@implements`, `@import`, `@overload`, `@property`, `@prop`, and with `--checked-types` also `@param` / `@arg` / `@argument` / `@return` / `@returns` lines that start with a `{type}`) keep only `@tag {type} name`.

## verify.mjs

`node verify.mjs <orig-dir> <current-dir> [--schema-tags] [--checked-types] [--list-frozen] [--line-limit <n>] [--files-from <list>] [files…]` runs three checks per file:

1. **Code check.** Markup (components) must be identical. Each script's Babel AST must deep-equal after dropping `start, end, loc, range, comments, leadingComments, trailingComments, innerComments, extra, tokens, errors`. Directives and the shebang (`program.interpreter`) are part of the AST.
2. **Layout check.** Remove every comment together with the spaces and tabs right after it, strip trailing whitespace, and compare the remaining non-blank lines exactly (indentation included). This also catches quote and number-format changes, which `extra` hides from the code check. Each line also carries its **gap**: the number of blank lines since the previous code line, or a wildcard when a comment that starts its line sits in that gap or opens the line. Gaps must match unless either is a wildcard, so blank lines may change only next to comments. In a component, lines carry their block index.
3. **Comment-is-code check.** Anchor every comment to the index of the next code token (`<block>:<index>` in components).
   - **Frozen whole** comments: identical text at the same anchor, none added or removed.
   - **Next-line directives** (`next-line`, `@ts-expect-error`, `@ts-ignore`, `prettier-ignore`, `translators:`, `biome-ignore`, `deno-lint-ignore`, `noinspection`, `istanbul` / `c8` / `v8 ignore next|start|else|if`): a directive that was the last comment before its anchor must still be.
   - **Frozen tag lines** (trimmed, one per line): identical multiset per anchor.
   - **Kept lines** must still exist at the same anchor; new ones may be added.
   - **Top-of-file comments** keep their line: a shebang on line 1 (frozen whole in every language; the Erlang, Haskell and Lua readers lex it as a comment, and a Stack `{- stack … -}` header is frozen whole), an encoding cookie (`# -*- coding: … -*-`) on line 1 or 2, `// swift-tools-version` on line 1, an escript's `%%!` emulator flags (frozen whole) on line 2 or 3. A comment added above them fails.
   - **Multi-line tags.** A tag line that opens more `(` / `{` / `[` than it closes is joined with the lines after it (stopping at a blank line or a new lower-case `@tag`) before it is classified, so a Doctrine `@ORM\Column(` … `)` block is one frozen line and a `@typedef {{` … `}} Row` is one kept key.
4. **Line limit** (with `--line-limit <n>`): a comment line that is new or edited, wider than `n` columns (tabs count as 4), prints `LONG COMMENT LINE: <file>:<line> (w > n)` and fails. In an edited comment, a line whose trimmed text was already in one of the original's changed comments is not new and is not checked; neither is a trailing comment whose code before it is already over the limit. Lines split on `\r?\n`, so a CRLF line ending adds no column.

Print `CODE CHANGED: <file>[: reason]`, `LAYOUT CHANGED: <file>:<line>` or `FROZEN COMMENT CHANGED: <file>: <text>` per failure, then `OK: N files, code identical (n frozen comments/lines protected)` or `FAILED: …`. Exit non-zero on any failure. A file missing from `<orig-dir>` or `<current-dir>` is a failure. `--list-frozen` also prints `FROZEN: <file>:<line> <text>` for every frozen comment and tag line of the original.

## coverage.mjs (tree-sitter languages)

`node coverage.mjs <dir> [--since] [--line-docs] [--files-from <list>] [--context-from <list>] [files…]` is the same command line as for JS / TS, with the same output. With `--line-docs`, plain line comments directly above a declaration count as its doc (in JS / TS, `//` comments; elsewhere, any prose comment, looking past Python decorators and Rust / C# attributes). Elixir skips `defimpl` bodies. `tsCoverage` applies `COVER[lang]` from `treesitter.mjs`: `need()` names a node that needs a doc comment (or returns null for an exemption), `documented()` looks for an adjacent doc comment (looking past attributes or decorators where the language has them; Python looks for a docstring in the body), and `header()` checks the file header. C / C++ headers are read first, so a definition whose prototype is documented in a header is exempt. `--context-from <list>` adds files that are read for those prototypes and for Go package docs but never reported on, so an agent's run over its own group sees documentation in other groups' files. Go needs one package doc comment per directory, reported as `MISSING PACKAGE DOC: <dir>`. Gaps print as `MISSING FILE HEADER: <file>` and `MISSING DOCBLOCK: <file>:<line> <node type> <name>`. With `--since`, a PHP, Java or Kotlin declaration that is documented but has no `@since` in its leading comments prints `MISSING @since: …`; other tree-sitter languages ignore the flag.

## coverage.mjs (JS / TS)

`node coverage.mjs <dir> [--since] [--line-docs] [--files-from <list>] [--context-from <list>] [files…]` prints one `MISSING …` line per gap, then `GAPS: n` (exit 1), or `OK: N files fully documented` (exit 0). A doc comment is a `/** … */` block attached to the node or to a wrapper (`export`, variable declaration, expression statement, assignment, TS wrappers). Gaps:

- No `/** … */` before the first statement or directive (a single doc comment that belongs to a first-statement declaration does not count as a file header). In a component, the first script block with code is checked.
- Undocumented: function and class declarations; `declare function`; interfaces, type aliases, enums, named namespaces; members of interfaces and of top-level object type aliases; class methods, getters and properties (skipping a constructor that only has parameter properties and an empty body, a property initialized with a bare `inject( … )` call, an implementation after overload signatures, and a setter paired with a getter); top-level `const` / `let` / `var` bound to a function, a class or a call with a function argument; any exported binding; `export default` of a function or a call with a function argument; `a.b = function …` assignments; block-bodied methods of exported object literals (and of `module.exports` / `exports.x` objects); and, outside test files, statements that call `.get/.post/.put/.patch/.delete/.del/.head/.options/.all/.use/.route/.param/.on/.once/.addListener/.addHook/.register/.handle/.process/.subscribe/.pre/.method/.static/.decorate/.decorateRequest/.decorateReply` with a block-bodied function argument or an object argument with a `handler` / `preHandler` / `preValidation` / `onRequest` / `preParsing` / `preSerialization` function; `.decorate` / `.decorateRequest` / `.decorateReply` calls always count, whatever value they add.
- With `--since`: a top-level declaration whose doc comment lacks `@since`.
- With `--line-docs`: a `//` comment directly above a declaration counts as its doc (not for the file header).
- The file header must have a prose line: a docblock of tags only (`/** @vitest-environment jsdom */`) does not count. In an Astro component the header is checked in the frontmatter only, and a component without frontmatter needs none.

## selftest.mjs (all languages)

For tree-sitter files, `tsMutations` supplies the insertion point (a top-level statement that starts its line with no comment above), a code edit (a number plus one, or an identifier with `X` appended), a joinable line break after `{`, `(`, `[` or `,`, and a deletable blank line between code tokens. Inserted comments use the language's line comment marker; the lint-directive case inserts `cspell:disable-next-line`. Where indentation is syntax (`indentSensitive`: Python, Haskell, and Lua, whose reader groups statements by column 0), a re-indented line may change the code, so `CODE CHANGED` also counts as flagged there.

## selftest.mjs (JS / TS cases)

`node selftest.mjs <project> <work-dir> [--schema-tags] [--checked-types] [--files-from <list>] [files…]` samples files (per extension the first, the largest and a test file, plus the first files with frozen, kept and next-line directive comments), copies them to `<work-dir>/orig/`, and runs verify on one mutated copy per case: unchanged (OK), added doc comment (OK), code edit (`CODE CHANGED`), re-indented line, joined lines and a deleted blank line between code lines (`LAYOUT CHANGED`, not `CODE CHANGED`), new lint directive, new frozen tag line (a deprecation in the language's form: `@deprecated`, Go `Deprecated:`, Python `.. deprecated::`; skipped where the language has none), deleted frozen comment, comment wedged under a next-line directive and removed kept tag line (`FROZEN COMMENT CHANGED`), and a blank line in component markup (`CODE CHANGED … markup`). It prints PASS / FAIL / SKIPPED per case and `SELFTEST OK` or `SELFTEST FAILED`.
