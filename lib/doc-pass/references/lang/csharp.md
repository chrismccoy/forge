## C# rules

### Files and tools

- In scope: `.cs`.
- Out of scope: `bin/`, `obj/`, `*.Designer.cs`, `*.g.cs` and other generated sources, files marked `<auto-generated>` (EF Core migration designers and the model snapshot included), `.csproj` and `.sln` files, `appsettings*.json`, `.resx`, Razor views and components (`.cshtml`, `.razor`), XAML.
- Syntax check: the checker parse after each file (agents); once per wave, the main session runs `dotnet build` in its work copy, never in the project (warnings as errors when the project sets it). Baseline the warning list before editing: with `GenerateDocumentationFile`, the compiler validates XML docs (CS1570 malformed XML, CS1572 and CS1573 `<param>` mismatches, CS1574 unresolved `cref`, CS1591 missing docs on public members), and analyzers (StyleCop, Roslynator, `.editorconfig` rules) may add more. New warnings are fixed in the comment.
- `dotnet format --verify-no-changes` before and after; the project's test runner (`dotnet test`).
- `dotnet format` whitespace rules read a doc comment and an adjacent misindented `#pragma` line (column 0 or a different indent) as one block of leading trivia, so a new doc comment beside it adds diagnostics even when the comment itself is indented correctly. In a file that already failed `dotnet format` at baseline, such new diagnostics are this case: leave them and note the file in your report. A file that passed and now fails needs its comment fixed.

### Doc comment style

- `///` XML doc comments (`/** … */` also counts; follow the project). `//` never counts.
- `<summary>`: third-person sentence ending in a period. Longer detail goes in `<remarks>`.
- `<param name="…">` per parameter, `<typeparam name="…">` per type parameter, `<returns>` unless `void` or `Task`, `<exception cref="…">` per exception thrown on purpose, `<value>` on a property when its meaning needs more than the summary. A positional record documents its parameters with `<param>` on the record.
- References: `<see cref="Type.Member"/>`, `<paramref name="…"/>`, `<see langword="null"/>`. Every `cref` must resolve, and a `cref` to an overloaded method names its parameter list (`HistorySearch()`, `HistorySearch(int)`): a bare name is CS0419.
- The XML must be well formed: write `&lt;`, `&gt;`, `&amp;` in text.
- Never repeat types. Say what they cannot: when `null` is returned, units, ranges, what a faulted `Task` means, cancellation.
- `<include …/>` lines are frozen: keep existing ones, never add one. `<inheritdoc/>` lines are kept: keep existing ones; a new one is allowed, but an interface implementation should get its own short `<summary>`.

### Coverage

- Every class, struct, interface, enum, record and delegate; every method, constructor, property, field and event, private members included (wider than CS1591).
- Exempt: `override` members, and test methods whose declaration's first line carries `[Fact]`, `[Theory]`, `[Test]`, `[TestMethod]` or `[TestCase]`.
- Checked by reading: enum members whose meaning isn't plain, indexers, operators, local functions, top-level statements in `Program.cs`.
- The doc comment sits directly above the declaration and its attributes, with no blank line between.
- No file header is scanned. A `///` comment above `using` or `namespace` is misplaced (CS1587): a file header, when wanted, uses `//` lines.

### Comments that are code

- Whole comment frozen when its first line starts with `ReSharper disable` / `ReSharper restore`, `<auto-generated`, `<copyright`, `dotcover disable` / `dotcover enable`, `cspell:`, `spell-checker:`, `noinspection`, `NOSONAR` or `language=`; and when any line starts with `@generated`, `@license`, `Copyright`, `(c) 2024`, `©`, `SPDX-License-Identifier`, `Permission is hereby granted` or `Licensed under the`, or names the GNU (Lesser, Affero) General Public License.
- Frozen lines: a doc line starting with `<include`.
- Kept lines (keep each exactly; new ones allowed): a doc line starting with `<inheritdoc`.
- `<see>` and `<seealso>` are ordinary prose to the checker: they may be edited, but every `cref` must still resolve.
- Last before its code: `ReSharper disable once`.
- Each `///` and `//` line is its own comment: never start any line with these words.
- Preprocessor lines (`#pragma warning disable`, `#nullable`, `#region`, `#if`) and attributes (`[SuppressMessage]`, `[Obsolete]`, `[GeneratedCode]`) are code.

### ASP.NET Core

- **Program.cs:** the header says what it builds: services registered, middleware pipeline, endpoints mapped, configuration sources. Middleware order is behavior: an inline comment before each group says why it sits there (`UseExceptionHandler` first, `UseRouting` before `UseAuthentication`, authentication before `UseAuthorization`, CORS before endpoints).
- **Route map:** minimal APIs (`app.MapGet`, `MapGroup` prefixes, `RequireAuthorization`) and controllers (`[Route]` on the class plus `[HttpGet("{id}")]`) give the full paths. Each endpoint: method and full path, policy or roles, inputs (route, query, body, headers) and validation (`[ApiController]` returns 400 on invalid model state), responses and statuses, exceptions mapped by the exception handler.
- **DI lifetimes:** each registration says singleton, scoped or transient when the reason isn't plain, and what the service holds. Hosted services (`BackgroundService`) say their schedule, cancellation and failure handling.
- **EF Core:** the `DbContext` lists its sets and the configuration in `OnModelCreating`; entities describe the table, each property, keys, indexes, navigations (loading strategy, cascade) and concurrency tokens. Queries say tracking or `AsNoTracking`, and what returns when nothing matches. A migration class's doc says what it changes and whether `Down` fully reverses it (`Up` and `Down` are overrides); never edit its code or name.
- **Options as the env map:** `IOptions<T>` / `IOptionsMonitor<T>` classes and `Configuration["Section:Key"]` reads form the env map. Document each key once: meaning, unit, default, required, secret. Environment variables use `__` for nesting (`Smtp__Host`). Never copy values from `appsettings*.json` or user secrets.
- **Comments a tool reads:** with Swashbuckle's `IncludeXmlComments`, `<summary>`, `<remarks>`, `<param>`, `<returns>` and `<response code="…">` on endpoints and DTOs become the published OpenAPI text. The rules file says whether the user accepted that. Write those comments for API consumers: no internal notes, no file paths.

### Bug report additions

- `async void` outside event handlers; blocking on tasks with `.Result`, `.Wait()` or `GetAwaiter().GetResult()`.
- `IDisposable` created without `using`; `HttpClient` created per request.
- A scoped service captured by a singleton; `DbContext` shared across threads.
- The null-forgiving `!` on values that can be null; N+1 queries from lazy loading; SQL built by string concatenation (`FromSqlRaw` with interpolation).
