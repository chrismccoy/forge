## TSDoc style (`.ts`, `.tsx`, `.mts`, `.cts`, `.d.ts`, and `<script lang="ts">` blocks)

- **Pick the dialect:** `eslint-plugin-tsdoc` (`tsdoc/syntax`) or a `tsdoc.json` means strict TSDoc: only tags it allows, and `@param name - Description.` with the hyphen. TypeDoc (`typedoc.json`, a `docs` script) means TypeDoc's tags are also fine (`@category`, `@group`, `@expandType`). `eslint-plugin-jsdoc` with a `*-typescript` config: follow its rules. With none, use the defaults below.
- **Never repeat types that the signature already states.** Write `@param id - User ID from the route.`, not `@param {string} id`. Write `@returns The saved note.`, not `@returns {Promise<Note>}`. Say in words what the type cannot say: units, ranges, formats, when it is `undefined` or `null`, and what a rejected promise means.
- **Voice:** a third-person summary ending in a period, then a blank line and `@remarks` for longer detail when the project uses TypeDoc or API Extractor; otherwise a plain second paragraph.
- **Tags:** `@param` for every parameter (for a destructured parameter, `@param props - …` then describe each used property in the interface's own member comments, not with dotted `@param` names, which strict TSDoc rejects). `@returns` unless the function returns `void` / `Promise<void>`. `@throws {@link NotFoundException}` when … (TSDoc form) or `@throws NotFoundException When …`. `@typeParam T - …` for each generic (not `@template`, which is JSDoc). `@example` only when the project already uses examples (and never when schema tags are on). `@defaultValue` on optional properties with a default. `{@link Name}` for cross references.
- **Interfaces and types:** a doc comment on the interface or alias, and on each member (`/** Heading text. */` above `title: string;`). Union members of a string-literal type are described in the alias comment. Enums: the enum, plus each member whose meaning isn't plain from its name.
- **Classes:** the class (its role and lifecycle: singleton provider, request-scoped, entity), each property (decorated DTO and entity fields included: say what the field means, not what the decorator does), each method. An `abstract` member says what implementers must do.
- **Overloads:** a doc comment on each overload signature; none on the implementation.
- **Declaration files:** document every `declare` function, variable, class, interface and member, and each member a `declare module` / `declare global` augmentation adds (`Request.user`, `Window.__APP_STATE__`, `ImportMetaEnv.VITE_API_URL`).
- **Inline comments:** `//` full sentences ending in a period.
